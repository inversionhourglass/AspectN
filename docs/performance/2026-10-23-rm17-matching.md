# RM-17 匹配阶段分配与耗时

日期：2026-10-23。对应[实施与回归记录](../reviews/2026-10-23-rm17-matching-allocations.md)。本轮建立有限场景的可复跑基准，并消除修饰符判断的临时集合；不作为整体吞吐保证或历史任务 35 的完整发布闸门。

## 测量方法

[基准工程](../../benchmarks/AspectN.Benchmarks/README.md)使用 BenchmarkDotNet 0.15.8、MemoryDiagnoser 和 .NET 10。每项运行两个独立进程，每进程三轮预热、六轮测量；计时器另执行框架默认的校准与开销测量，统计采用其默认异常值处理。样本数因此可能少于 12，原始样本和统计摘要保留在数据文件中。

初始候选由 Reflection 映射，表达式在 GlobalSetup 编译；Setup 验证每种输入的预期 Matched/NotMatched 及零诊断。计时方法只返回已编译模式 Match 的状态，避免输出成本进入计时。祖先场景仍包含 Match 内部的真实闭包查询及必要的祖先映射，不是纯中立比较器微基准。每项均使用生产默认预算。

生产基准为 `a8b19b12491646f46ff79866368ab3c29e328acf`。先以原 ModifierMatcher 运行 before，再仅修改该生产文件运行 after；两轮基准输入、运行时、作业设置保持相同。测量期间不并行构建或运行测试；两轮之间完成生产修改、回归及格式检查。除注释精确化外，基准计时代码保持一致。

机器为 Windows 11 25H2（10.0.26200.9711）、Intel Core i9-13900H（14 物理核、20 逻辑核）、x64；SDK 10.0.401，运行时 .NET 10.0.12，RyuJIT，Concurrent Workstation GC。BenchmarkDotNet 使用高性能电源计划。当前进程没有附加调试器。

在仓库根目录运行：

```powershell
dotnet run --project benchmarks/AspectN.Benchmarks/AspectN.Benchmarks.csproj -c Release -- --validate
dotnet benchmarks/AspectN.Benchmarks/bin/Release/net10.0/AspectN.Benchmarks.dll --filter '*' --artifacts artifacts/rm17/before
# 将生产实现改为优化版本并重新构建、验证后，使用相同设置运行：
dotnet benchmarks/AspectN.Benchmarks/bin/Release/net10.0/AspectN.Benchmarks.dll --filter '*' --artifacts artifacts/rm17/after
```

before、after 各包含全部 18 个参数组合。这里的 before 表示基准生产实现，不能对同一个已优化 DLL 仅改输出目录就当作修改前数据。新工程不在原基准提交中；复跑对照须保留同一基准工程，以该提交的 ModifierMatcher 源码与当前优化源码分别构建。

本机的 `dotnet run`/直接 apphost 启动在创建 BDN 日志时遇到 UnauthorizedAccessException；用 `dotnet` 直接执行 DLL 成功。失败发生在测量前，失败日志也保留在 `artifacts/rm17`，没有当作产品失败或性能样本。

## 解释与限制

局部分配回归在计量外绑定模式、构造上下文并预热，只测已知元数据的修饰符 Evaluate：原实现四组双修饰符输入各为 40,960 B/256 次，即每次 160 B；优化后每组为 0 B，空修饰符对照前后为 0 B。计量包含成功、失败、权限备选和否定，不使用墙钟阈值。

完整 Match 仍有上下文、类型匹配、后端查询等分配。此处不把普通方法与修饰符场景的全部耗时差归因于单个内部操作，也不依据本次聚合数字宣称已经隔离 Fork、Split 或 DP 数组各自的成本。后续若优化类型链、命名空间或分支状态，需要保持同类对照并补充更有针对性的剖析。

耗时存在明显轮次波动，两个进程和固定少量迭代不足以支撑跨机器的速度承诺。本轮将确定的字节差作为优化收益；耗时及误差仅作为本机观察值，不凭均值变化或一次顺序对照宣称因果提升。基准未进入 CI 的硬性时间阈值。

未测冷启动、解析/绑定、初始映射、Cecil/Roslyn/Fody 关系查询、.NET Framework 性能、极端预算输入、所有表达式或多线程负载。Declaration/Capture 在开放变量场景中的内部工作不同，其耗时不能用来推断其中一种模式在所有表达式上必然更快。
