# O-02：Rougamo式版本号策略实施计划

**目标：** 集中维护三段VersionPrefix；正式tag必须为v加基础版本；预发布统一使用preview-时间戳后缀，整次流程只生成一次完整版本。

**基准：** `cc69141362727fc2ae9154467970865c5327ccc4`。现有SDK求值为VersionPrefix/Version/PackageVersion=1.0.0、VersionSuffix为空，本轮显式保留1.0.0。当前检出实施，保留README及既有未跟踪资料，不推送、签名或发布，不修改Rougamo。

**结构：** Directory.Build.props集中基础版本；eng/get-release-version.ps1只读解析唯一无条件的VersionPrefix，校验正式tag或生成一次UTC Unix毫秒时间戳，输出VersionPrefix、VersionSuffix、Version的JSON。Release沿用同一受保护环境和签名前校验，使用输出贯穿还原、构建、测试、打包、包/消费者校验及交接。维护者进一步确认：推送prerelease分支自动预发布，dev的push验证保持，不增加手动版本覆盖入口。

1. 新增eng/tests/get-release-version.Tests.ps1黑盒回归，覆盖正式版本、一致性拒绝、+metadata/预发布tag拒绝、非法或多义基础版本、预发布一次生成的完整版本及只读行为，先观察未实现的失败。通过既有安全夹具辅助函数管理本次目录。
2. 新增版本解析脚本并显式集中1.0.0。Windows PowerShell与PowerShell7执行同一回归；以MSBuild核对五个发布项目的默认和预发布属性，不新增任意版本覆盖入口。
3. 接入发布入口，正式tag在还原前检查；预发布只读取一次时钟，后续共用一个版本。保留所有现有构建/测试、包和消费者校验、摘要、签名、保护环境及上传步骤；CI/Compatibility的dev/main规则保持，仅接入版本辅助回归。
4. 实际生成正式/预发布各五对本地包，核对版本、内部依赖及符号元数据。既有消费者阻塞如未解决须照实保留，不以局部元数据成功宣称完整发布恢复；不执行真实签名、推送或发包。
5. 同步发布指南、INV-0021及受影响兼容说明、处置报告/数据与未跟踪清单；文档生成及-Check、严格校验、工作流结构与实际版本步骤检查、diff核验后，经独立只读审查仅提交本项。

## 执行结果

五步已实施。版本脚本两个宿主各23项、实际工作流版本步骤9项通过；五个项目的默认版本保持1.0.0。正式版与预发布版各五对包的内容、依赖、符号和全部nuspec版本核验通过，同一预发布版本属性下完整2436项测试通过。两轮解决方案构建各零错误并保留既有net472的MSB3277警告；消费者未重跑，既有Roslyn/net472阻塞继续保留。

知识库生成、-Check及严格文档检查通过，0错误、0告警；派生矩阵由生成器同步INV-0021主题和备注。源实现及最终文档与证据的两轮独立只读审查均无可操作问题。细节、环境重试和证据范围见[处置报告](../reviews/2026-10-24-o02-release-version-policy.md)及数据。未推送、签名或发布。
