## 1. 整体方案与公开 API

采用三个独立、不可变的配置类型。各阶段自行选择限额，不要求共享实例或使用相同数值。

| 配置类型 | 配置归属 | 生效范围 |
| --- | --- | --- |
| `AspectNParseOptions` | 解析或编译入口 | 源码解析、语法树校验及绑定 |
| `AspectNMappingOptions` | 适配器实例 | 原生元数据映射 |
| `AspectNMatchOptions` | 编译计划 | 候选预检查、表达式求值及类型系统查询 |

配置对象只保存限额，所有属性只读；本次操作已消耗的额度由独立上下文保存。同一配置或编译计划可以并发复用，不共享不同操作的计数。

统一使用以下限额值类型：

```csharp
ResourceLimit.Finite(128)
ResourceLimit.Unlimited

TimeLimit.Finite(TimeSpan.FromMilliseconds(250))
TimeLimit.Unlimited
```

- `ResourceLimit` 的有限值采用正数 `long`；零、负数和显式传入的无效默认结构值均拒绝。
- `TimeLimit` 的有限值必须处于所有目标运行时支持的正则超时范围。
- 配置构造参数省略或传入 `null` 表示使用该项默认值；只有显式 `Unlimited` 才表示不限。
- 配置按字段值参与缓存键，包含有限值与无限值的区别。
- `Unlimited` 只关闭对应限额；取消、其他限额及签名合法性检查继续生效。声明两个泛型槽位却提供一个实参，仍在构造签名时被拒绝。
- 不使用 `int.MaxValue` 伪装无限额度；无限额度不累积无意义计数，有限额度使用剩余额度检查避免溢出。

公开入口统一调整为以下形态，选项可省略、取消令牌默认为 `default`：

```csharp
AspectNParser.Parse*(source, parseOptions, cancellationToken)
AspectNEngine.Compile*(source, parseOptions, compilationOptions, cancellationToken)
AspectNCompilation.Create(tree, compilationOptions, cancellationToken)
```

`AspectNCompilationOptions` 保留 `GenericVariableMode` 并引用 `MatchOptions`；现有 Capture 预算和正则超时迁移到 `AspectNMatchOptions`。泛型变量模式默认仍为 `Declaration`。

语法树保留实际使用的 `ParseOptions`；编译既有语法树时不能覆盖此前的解析限制。`AspectNCompilation.Options` 与 `CompiledPattern.Options` 引用同一份不可变编译选项，由其持有 `MatchOptions`，不为每个查询重复传递配置。`Compiled*.Match` 继续接收候选、类型系统和取消令牌，不提供逐次覆盖匹配选项的入口。

映射选项保存在映射器或适配器实例中。内置类型系统另外保存用于独立公开查询的默认 `AspectNMatchOptions`，通过构造参数配置；匹配器发起内部查询时使用编译计划的匹配选项，不与实例的独立查询默认值取最小值或叠加。中立签名只保存元数据，不保存某次操作的策略和累计计数。

按统一新 API 迁移调用者，不保留两套配置来源。移除表示固定策略的 `AspectNLimits`，默认值由各选项类型提供。

## 2. 配置项与已采纳的默认值

### 2.1 解析配置 `AspectNParseOptions`

| 配置项 | 默认值 | 含义 |
| --- | ---: | --- |
| `MaximumSourceLength` | 256 | 传入解析 API 的完整表达式长度，按 UTF-16 代码单元计数，即 .NET `string.Length` |
| `MaximumTokens` | 1,024 | 实际词法处理产生的非 EOF token 数 |
| `MaximumSyntaxNodes` | 2,048 | 实际创建的语法节点数，包含语法 token |
| `MaximumParserDepth` | 128 | 解析器逻辑调用帧的嵌套深度 |
| `MaximumSyntaxDepth` | 256 | 最终语法树深度 |
| `MaximumTypeDepth` | 64 | 类型模式的结构深度 |
| `MaximumTypeGenericParameters` | 64 | 类型的有效泛型槽位数，包含外层类型 |
| `MaximumMethodGenericParameters` | 64 | 方法自身的泛型槽位数 |

源码长度包含空白、换行、限定类型名、正则内容及表达式自身的转义字符；检查前不通过删空白或裁剪规避限额。它不计算宿主 C# 字符串字面量外围的引号，也不按 UTF-8 字节数计算。

类型、语法树和逻辑帧的根深度均计为 1，保留现有结构展开口径。词法前瞻和错误恢复如果发生重新扫描，其 token 和临时节点也计入本次操作，不能重新获得额度。绑定阶段使用语法树保存的配置校验泛型条款。

默认值依据：本轮对仓库测试及使用示例中直接作为解析、编译首参数的字符串字面量做抽样，取得 64 个不同的解析有效样例；最长 77 个 UTF-16 代码单元，最终语法树最多 69 个节点、39 个 token、深度 10。该样本不覆盖变量、拼接、生成器及间接传参，不是生产负载统计，最终节点计数也不包含重新扫描产生的临时消耗。token 与节点默认值因此保留余量；既有深度与泛型槽位默认值不继续收紧。

### 2.2 映射配置 `AspectNMappingOptions`

| 配置项 | 默认值 | 含义 |
| --- | ---: | --- |
| `MaximumTypeDepth` | 64 | 原生类型结构深度 |
| `MaximumTypeGenericParameters` | 64 | 类型有效泛型槽位数 |
| `MaximumMethodGenericParameters` | 64 | 方法自身泛型槽位数 |
| `MaximumWork` | 100,000 | 一次映射累计处理工作量 |
| `MaximumAttributeRecords` | 1,024 | 一次映射累计扫描的特性记录数 |
| `MaximumGeneratedTextLength` | 16,384 | 每个生成的类型文本、缓存键文本或 `OwnerId` 的 UTF-16 长度 |

一次最外层 `MapType`、`MapTypeUse`、`MapMethod` 或 `MapProperty` 为一个映射操作。其声明类型、返回值、参数、原始定义、特性及自定义修饰符映射共享预算。独立显式映射入口创建新操作上下文。

Cecil 在现有 `CecilMappingOptions` 中增加 `Resources`，继续保留 `LeaveOpen`。Reflection、Roslyn 的映射器和类型系统构造入口接收 `AspectNMappingOptions`。公开映射入口增加取消令牌。

### 2.3 匹配配置 `AspectNMatchOptions`

| 配置项 | 默认值 | 含义 |
| --- | ---: | --- |
| `MaximumTypeDepth` | 64 | 候选及查询涉及类型的结构深度 |
| `MaximumTypeGenericParameters` | 64 | 类型有效泛型槽位数 |
| `MaximumMethodGenericParameters` | 64 | 方法自身泛型槽位数 |
| `MaximumWork` | 250,000 | 整次匹配累计工作量，两种泛型模式均适用 |
| `MaximumRelationNodes` | 1,024 | 累计展开的关系图节点数 |
| `MaximumRelationEdges` | 4,096 | 累计考察的关系图边数 |
| `MaximumAttributeRecords` | 1,024 | 累计扫描的特性记录数 |
| `MaximumCanonicalSignatureLength` | 16,384 | 每个规范化签名文本的 UTF-16 长度 |
| `MaximumBindingAlternatives` | 256 | Capture 模式每个收集器存活的不同绑定备选数 |
| `MaximumBindingWork` | 50,000 | Capture 模式累计绑定处理工作量 |
| `RegexTimeout` | 250 ms | 单次正则匹配超时 |

全部限额均支持显式 `Unlimited`，包括 Capture 预算和正则超时。`Declaration` 模式继续不创建 Capture 的绑定环境和备选收集器，但受到通用工作预算约束。

表达式长度与候选元数据规模分别估算：单字符 `*` 也能匹配复杂类型，所以映射、匹配限额不按源码长度同比缩小。匹配总工作预算高于映射和 Capture 专项预算，为候选预检查、多个后端查询、比较和文本处理保留空间。短正则仍可能处理长签名并产生大量回溯，正则默认超时保留现有值。

新增工作量默认值属于设计估算，实施计数后必须使用正常样例和压力场景验证，不能直接解释为耗时保证。若验证需要调整已采纳的默认值，应列出证据并重新讨论，不能静默改值。

编译缓存容量继续由 `AspectNEngineOptions.CacheCapacity` 管理，保留默认 256、零表示关闭，不引入无限缓存。

## 3. 预算计数与内部执行状态

### 3.1 工作量规则

`MaximumWork` 衡量处理规模，不表示毫秒或内存字节数。以下动作在执行前扣减相应额度：

- 访问表达式求值节点、原生元数据或中立签名节点。
- 考察继承、接口、泛型约束或合成关系边。
- 扫描特性记录，包括最终被过滤掉的记录。
- 比较、散列、复制、合并或去重绑定条目。
- 处理字符串字符，包括生成文本以及比较、散列所需的字符量。

专项计数同时消耗总工作额度，同一动作在同一作用域内不能重复扣减总工作量。重复关系边仍消耗边额度；绑定去重即使没有增加备选数，也消耗工作额度。关系节点按每次查询中新展开的节点计数，不同查询重新展开同一祖先时继续累计。

缓存命中按实际执行的工作计数，因此可能比冷缓存消耗更少；结构深度和泛型元数检查不能通过缓存绕过。元数据预检查同样计入匹配预算，不能先无预算地遍历全部输入。

### 3.2 上下文内容与生命周期

`TypeSystemQueryContext` 调整为仅供 Core 与内置后端使用的内部类型，不进入公开 API。它将一次操作的选项引用、取消控制和累计预算传给内部查询逻辑；也可以由现有内部 `EvaluationContext` 持有这部分状态。普通调用者和第三方 `ITypeSystem` 实现者无需创建或传入该上下文。

| 内容 | 拟定成员或职责 |
| --- | --- |
| 本次匹配限额 | 内部只读 `Options`，引用编译计划或独立查询实例的不可变 `AspectNMatchOptions` |
| 本次取消控制 | 内部只读 `CancellationToken` |
| 本次已用或剩余额度 | 内部保存，不允许重置 |
| 预算扣减入口 | `TryConsumeWork`、`TryConsumeRelationNodes`、`TryConsumeRelationEdges`、`TryConsumeAttributeRecords` |
| 资源中止状态 | 内部只读 `IsExhausted`、`LimitDiagnostic`，保留首个资源失败 |
| 嵌入操作的中止传播 | `ReportResourceLimit(AspectNDiagnostic diagnostic)`，接收 `AN3007`、`AN3008` 诊断 |

`TryConsume*` 接收正数计数，先检查取消，再原子检查并扣减总额度及专项额度；失败时不执行对应工作，并记录中止状态。计数支持线程安全共享，不提供重置方法。

Core 每次 `Match` 创建一个上下文，同次求值的分支及后端调用共享累计预算；不同 `Match` 使用不同上下文。上下文不保存在编译计划或适配器实例中，不使用 `ThreadStatic`、`AsyncLocal` 或全局可变配置。

独立调用内置类型系统公开方法时，方法从实例保存的默认查询选项及本次取消令牌创建新内部上下文。每次独立公开调用单独计数；不提供让调用者手动拼接多次查询为一个共享预算操作的公开上下文入口。

上下文不携带 Cecil、Roslyn、Reflection 原生对象，也不公开 Core 的 AST、变量绑定环境或内部 `EvaluationContext`。后端只获得执行查询所需的资源与取消控制。

### 3.3 `ITypeSystem` 与比较入口

公开 `ITypeSystem` 采用以下形态，取消令牌可省略、默认为 `default`：

```csharp
AreEqual(left, right, cancellationToken)
IsAssignableTo(candidate, target, cancellationToken)
GetInheritanceClosure(candidate, cancellationToken)
HasDirectAttribute(target, attributeType, cancellationToken)
```

返回类型、`Capabilities` 和查询语义保持不变。当前 `AreEqual` 尚无取消令牌，需要同步升级其声明及实现；其余方法保留普通取消参数。第三方无需实现公开资源计数协议，也不新增公开的非限定查询目标比较器。

Core 定义内部查询接口 `IBudgetAwareTypeSystem`，通过内部派发器传递同次匹配的上下文；内置后端显式实现该接口，避免产生接收上下文的公开重载。Core 对 Cecil、Cecil.Fody、Roslyn、Reflection 四个程序集授予必要的友元访问，保持核心公共 API 不引用任何后端类型。内置公开方法与内部接口共用同一查询实现，但分别使用独立调用上下文与匹配共享上下文。

`StructuralTypeComparer` 的公开入口只接受两个类型、可选的不可变 `AspectNMatchOptions` 和取消令牌；其内部入口复用已有预算。无宿主实例的独立工具方法可以接受配置对象，不暴露执行上下文。

内置后端在遍历节点、关系边和特性前使用内部扣减入口。Core 在后端返回后和最终结果发布前检查中止状态，防止局部 `Matched` 掩盖已耗尽的预算。

模型自身的 `TypeIdentity.Equals`、`GetHashCode` 等仍保留普通值操作语义；受预算约束的查询路径必须显式计量身份链及字符串比较，不能用一次未计费的深层模型操作绕过限额。

### 3.4 查询内的映射

内置后端每次查询创建一个映射子上下文，使用适配器固定的 `MappingOptions`；该查询内部所有原生映射共享子预算，同时消耗外层匹配预算。特性扫描同时计入适用的映射、匹配特性额度；每个作用域内的总工作量仅扣一次。

映射器接收查询上下文的入口保持内部可见，不提供公开的 `Map*(queryContext, nativeValue)` 重载。内置类型系统复用同一子上下文，不为每个祖先重新调用独立映射入口以重置预算。公开映射方法使用实例保存的映射配置及本次取消令牌，创建独立映射预算。

映射工作量、特性扫描或文本长度超限必须通过资源中止通道通知外层上下文。显式映射仍抛限额异常，查询边界将限额异常转为相应的 `Unknown`。单个类型的深度、元数超限不设置整次操作中止标记，保留 C05 的分支级行为。

### 3.5 第三方后端的计量边界

第三方 `ITypeSystem` 通过普通公开接口调用，Core 仍对自身的预检查、求值、绑定、格式化、查询派发和结果处理累计计费，向后端传递原取消令牌，并在查询返回后重新检查取消。对返回闭包的消费继续执行结构限制及 Core 可观察的节点处理限制。

Core 无法知道第三方内部展开了多少节点、考察了多少边或扫描了多少特性，也不能抢占忽略取消的实现。对于仅实现公开接口的第三方，不承诺将其内部全部工作精确纳入匹配累计预算，也不能通过检查返回集合限制它在返回前已经分配的内存。完整的后端内部计量适用于内置后端；第三方负责自身内部的资源控制。

第三方若返回带 `AN3007`、`AN3008` 的资源耗尽结果，Core 在查询边界将其记录为整次操作中止；`AN3005`、`AN3006` 仍按单项结构失败处理。普通未知事实不设置资源中止标记。

第三方装饰器即使内部调用内置后端的公开方法，也不会自动获得内部共享预算通道：其内层公开调用使用各自的独立预算，Core 仅按上述第三方边界处理。不得用 `AsyncLocal`、`ThreadStatic` 或适配器实例上的可变“当前操作”字段绕过这一边界。以后若要求第三方提供完整跨查询计量，需要另行设计明确的接入协议，不在本方案中隐式承诺。

## 4. 失败规则、算法与缓存

### 4.1 失败与诊断

| 场景 | 行为 |
| --- | --- |
| 无效配置 | 构造选项时抛 `ArgumentOutOfRangeException` |
| 解析资源超限 | 错误诊断，编译不可用 |
| 显式映射超限 | 抛 `AspectNLimitException` |
| 匹配或查询的资源预算耗尽 | 整次操作返回 `Unknown` |
| 取消 | 抛 `OperationCanceledException` |

- 解析新增资源限制使用 `AN1003`；既有深度、泛型条款诊断保留 `AN1002`、`AN2011`。
- 类型深度、泛型元数保留 `AN3005`、`AN3006`。
- Capture 专项预算保留 `AN3007`。
- 新增工作量、关系遍历、特性扫描及文本限制使用 `AN3008`。
- 正则超时保留 `AN3003` 和原有局部三态逻辑；规范化文本超限改用 `AN3008`，真正缺少可格式化信息时继续使用原有诊断。

诊断消息包含阶段、配置项、限额、已用量或请求量，并保留可获得的源码位置及此前诊断。取消优先传播；不捕获任意外部异常，也不提供 OOM 恢复。

保留 C05 的区别：单个祖先结构超限时，该分支产生 `Unknown`，仍可检查其他合法祖先；资源预算耗尽时中止整次操作，其他分支的成功不能覆盖它。达到文本长度限制也属于资源中止。

独立继承闭包查询可以返回已知前缀及 `Unknown` 失败标记，但不能宣称结果完整；匹配器看到上下文已中止时，不使用前缀给出确定结果。

损坏程序集的必要方法签名仍拒绝映射，不增加 U01 所排除的兼容恢复。既有 C01—C07、D01、U01 的其他语义继续保留。

### 4.2 深度与分配控制

不能只把常量替换成参数。所有依赖深度上限避免栈溢出的处理改用显式工作栈，包括两条解析路径、错误恢复、绑定、类型及成员求值、逻辑组合、参数匹配、规范化文本、原生类型文本、声明身份、修饰符及尚存递归的元数据辅助路径。

保留求值顺序、变量作用域、诊断及三态逻辑，不通过重排布尔表达式改变语义。清理泛型槽位命名等辅助代码中的隐含 64 上限。

解析资源耗尽后立即停止扫描，不再为了恢复而读取到 EOF；使用固定大小的恢复节点及诊断保留结果，其分配使用常量大小的紧急保留额度。各阶段在受控分配或扩展集合前检查预算，不能发布不完整的根映射或快照；已完成的独立子缓存条目可以保留。

`Unlimited` 不再依赖旧深度常量保护调用栈，但仍受运行时可表示范围和外部 API 能力约束。不新增全局字节、墙钟或缓存预算，也不承诺外部运行时能构造任意深度的类型。

### 4.3 编译缓存与取消隔离

缓存键包含源码、解析入口种类、全部解析选项、泛型变量模式及全部匹配选项；不包含后端映射配置。

缓存只复用已完成的编译结果。并发未命中时，各调用使用自己的取消令牌编译，完成后竞争发布，避免共享 `Lazy` 捕获首个调用者的令牌。正常完成的诊断结果可以缓存，异常和取消不缓存。

缓存命中前检查取消；源码长度检查应早于昂贵的缓存键散列。

## 5. 实施顺序与验收

分为五组可审查变更，每组同步必要调用者并保持可构建：

1. 引入限额值类型、三个配置类型，统一迁移公开入口、缓存键及 `AreEqual` 的取消签名，并建立内置后端的内部查询通道。
2. 改造前端工作栈、解析额度及停止恢复行为。
3. 实现匹配总预算、专项预算及规范化文本限制。
4. 接入 Cecil、Reflection、Roslyn、Fody 的映射及查询预算，完成中止传播。
5. 同步规范、迁移指南、第三方后端接入说明、知识库和验证证据，并完成第 5.1 节规定的公开配置 XML 文档。

### 5.1 公开配置的 XML 文档

公开配置的 XML 文档是实现的组成部分，不能以 Markdown 指南链接代替，也不能仅使用“获取最大值”一类重复属性名的说明。按仓库规则使用英文，中文说明同步到相应使用指南；调用者应能直接从 IDE 的类型、构造参数和属性提示中理解配置。

适用范围包括三个阶段选项类型、`ResourceLimit`、`TimeLimit`、编译选项和适配器上的配置入口，以及受限制的公开解析、映射、匹配和查询入口。逐项说明：

- **用途和范围：** 限制哪类输入或工作，在哪个阶段生效；按单次调用、整次匹配、单个文本还是单个 Capture 收集器计数；配置保存在何处以及是否可并发复用。
- **默认值和单位：** 写出准确默认值，并区分 UTF-16 代码单元、token、节点、边、泛型槽位、逻辑工作单位和时间。明确深度根节点计为 1、类型泛型槽位包含外层类型，以及前瞻重新扫描是否重复计数。
- **边界和有效值：** 恰好达到上限仍允许，申请下一项而超限时拒绝；说明有限值必须为正数、参数省略或 `null` 使用默认值、显式 `Unlimited` 关闭对应限额，以及默认结构值的有效性。
- **相互作用：** 专项限制与总工作量限制同时生效；放宽一个阶段或关闭一项限制不会自动放宽其他项。说明 `Declaration` 模式不使用 Capture 专项额度，独立查询默认选项与编译计划匹配选项的适用入口不同。
- **超限和取消：** 在适用操作入口说明诊断、`Unknown`、`AspectNLimitException` 和 `OperationCanceledException`；区分配置构造时的参数异常与后续执行超限，不给不会抛异常的只读属性虚构异常契约。
- **覆盖边界：** 工作量不等于耗时或字节数；第三方后端的隐藏内部工作不属于 Core 可精确计量的范围；`Unlimited` 不取消结构合法性检查或运行时限制。公开文档不要求用户管理内部执行上下文。

使用 `<summary>` 解释用途，使用 `<value>`、`<param>`、`<remarks>` 和适用的 `<exception>` 补充契约；需要示例时使用 `<example>`、`<code>`，并通过 `<see cref="..."/>` 引用相关公开选项或成员。

以下容易混淆的概念必须给出简短示例，说明放在最相关的公开类型或成员上，其他成员可以交叉引用：

1. **源码长度：** 以传入字符串的 `.Length` 为准，包含空白和表达式转义字符，不计算宿主 C# 字符串外围引号；说明非 BMP 字符占两个 UTF-16 代码单元及 256/257 的边界。
2. **结构深度与泛型槽位：** 对比简单类型和数组包装的深度，展示嵌套泛型类型的外层槽位如何计入类型有效元数，以及方法槽位独立计算。
3. **预算作用域：** 同次匹配的多次内置查询共享额度，不同 `Match` 独立计数；直接调用类型系统公开查询方法时，每次调用创建独立预算。
4. **专项限制：** 解释绑定去重仍消耗工作量、未增加备选数不等于没有处理成本；解释短查询表达式也可能处理很长的候选签名。
5. **配置调整：** 展示通过构造选项提高有限值、显式使用 `ResourceLimit.Unlimited` 或 `TimeLimit.Unlimited` 的方式，并说明其他限制仍然生效。

示例使用最终真实 API，保持简短并验证可编译；涉及匹配结果或超限行为的示例同时核对结果及诊断。验证采用现有样例或相应行为回归，不新增只比较 XML 文本的重复测试。

### 5.2 行为与文档验收

验收覆盖以下场景：

- 每项限额的默认值、降低、提高、`Unlimited`、恰好达到和超过一项的边界；无效计数、超时及默认结构值。
- 三阶段独立配置，放宽上游不自动放宽下游，关闭一项不关闭其他限额。
- 256 字符的长度边界，空白、换行、转义、非 BMP 字符的计数，以及前瞻、错误恢复和临时节点的实际消耗。
- 超过旧 64 层或 64 个泛型槽位的合法输入，以及深层输入的小栈隔离进程验证。必要时显式提高各项前端限额；真实后端无法构造的形状与中立合成输入分别取证。
- 宽关系图、重复边、特性扫描、绑定复制及去重、长文本、多次查询的累计计数与检查先于受控分配。
- 查询内部映射先耗尽预算、OR 另一分支成功、后端忽略扣减失败仍返回成功等中止传播场景。
- 内置后端内部计量、独立公开查询分别创建预算、第三方普通接口回退和装饰器边界；确认不存在公开上下文类型、参数或映射重载，第三方返回资源诊断仍触发整次操作中止。
- 并发匹配计数隔离；并发编译中一个调用取消不影响其他调用；缓存不保存取消或异常。
- 冷热缓存的结构检查一致性与实际工作计数，三后端、Fody、兼容宿主及既有 C01—C07、D01、U01 回归。
- 核对每项公开配置及其构造参数均满足第 5.1 节要求，默认值、单位和作用域与实现一致；XML 交叉引用有效，示例可编译且行为正确。
- 正常样例和压力场景验证新增默认值；Release 全解决方案构建、测试、格式检查、文档检查及知识库派生文件 `-Check` 通过。
