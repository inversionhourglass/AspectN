# 泛型变量双模式与捕获预算设计

**日期：** 2026-10-21。**状态：** 已批准实施。维护者在本设计提交 `7b86bbf` 后明确要求“开始实施”；当前变更落实本设计，同步规范、测试和知识库。第 7、8 节保留最初设计交付及可实施性复核的历史范围，当前实施证据见第 9 节。

## 1. 用户要求与设计目标

用户希望保留两种能力：默认采用 Rougamo 所代表的声明泛型形参占位符方式；通过配置显式启用 AspectN 当前更通用的类型捕获，并为捕获方式加入资源预算。

本设计保留同一套 Standard 文本语法、元数据模型和后端接口。模式由编译配置决定，不引入 Legacy 语言、第二套解析器或对 Rougamo 的产品依赖。Rougamo 的槽位做法是语义参照；AspectN 继续使用自己的声明身份及跨后端签名。

目标是让默认路径不再建立动态绑定备选集，同时使捕获路径在资源耗尽时有明确、有界、不会伪造确定结果的退出通道。不把“预计减少复制与分配”写成已经测得的性能结论，也不承诺所有继承、特性或第三方查询具有固定耗时。

## 2. 配置入口与公共 API 草案

新增核心枚举 `GenericVariableMode`：

| 值 | 语义 |
| --- | --- |
| `Declaration = 0` | 默认模式，变量是确定声明槽位的别名 |
| `Capture = 1` | 保留当前通用捕获、绑定备选及不确定性传播；新增有限预算 |

配置放在不可变的 `AspectNCompilationOptions` 中，由 `AspectNEngine.CompileMemberExpression`、`CompileTypePattern` 以及 `AspectNCompilation.Create` 的现有 options 参数传入。编译后的模式固定，不在单次 `Match` 上切换，因为变量合法声明位置和绑定节点不同。

保留现有 `AspectNCompilationOptions(TimeSpan? regexTimeout = null)` 构造器及二进制签名，使其产生 Declaration 模式。新增重载的参数为 `(TimeSpan? regexTimeout, GenericVariableMode genericVariableMode, int maximumBindingAlternatives = 4096, long maximumBindingWork = 1_000_000)`。前两个参数必填，避免与原构造器的 null、default 和位置调用产生重载歧义。暂不为便捷性再增加工厂或第三个构造重载。

```csharp
// 默认引用声明槽位，显式选择 Capture 时使用有限捕获预算。
var engine = new AspectNEngine();
var defaultCompilation = engine.CompileMemberExpression(expression);

var captureOptions = new AspectNCompilationOptions(
    regexTimeout: null,
    genericVariableMode: GenericVariableMode.Capture,
    maximumBindingAlternatives: 4096,
    maximumBindingWork: 1_000_000);
var captureCompilation = engine.CompileMemberExpression(expression, captureOptions);
```

以上名称、重载形状及预算默认数值是本设计的建议，不冒充用户已逐项指定。4096 与 1,000,000 作为初始建议值，实施时以正常样例和有界压力测量核对；若需要改值，在交付证据中给出数据和理由，不静默增加无限模式。

选项公开只读的模式、最大备选数和最大工作量。无效枚举、非正限额抛 `ArgumentOutOfRangeException`；所有构造路径统一验证，即使 Declaration 不消耗捕获预算也不接受非法值。捕获预算不允许零表示无限，不增加关闭预算的开关。原有有限 RegexTimeout、取消及其他结构上限保持。

编译缓存键必须按值包含源码、ParseKind、RegexTimeout、GenericVariableMode 和两个预算。相同值的选项可复用；不同模式或预算不能串用。语法解析树仍可相同，绑定后的计划不能混用。

## 3. Declaration 模式的变量语义

### 3.1 变量表示声明槽位

例如：

```csharp
public class Service
{
    public T Echo<T>(T value) => value;
}
```

```text
method($X Service.Echo<$X>($X))
```

编译时将 `$X` 解析为“当前候选方法的第零个声明形参槽位”的引用。匹配时取得真实声明形参身份，检查返回和参数是否引用同一形参。不把 int、string、List<int> 等构造类型作为该占位符的新取值，也不枚举其他类型寻找绑定。

槽位身份使用当前中立模型的 owner kind、owner ID、owner assembly 和 position；嵌套类型使用已有 CLI 槽位展开规则。不能仅比较形参名字、显示文本或 position。类型的第零槽和方法的第零槽不同，同名形参、不同声明及 C01 自定义修饰符相关身份不能混同。沿用已有身份模型，不重新设计其编码。

新声明处必须确认实际泛型项是该声明自身对应槽位的形参。构造为具体实参的 `Echo<int>`、`Owner<int>` 不因提供 OriginalDefinition 而自动回退成开放定义；外部形参构造的开放引用也不能冒充该声明自身槽位。调用方要匹配原始定义时显式映射/传入原始定义。

这只约束变量，不禁止具体模式：`List<int>`、`Owner<int>.Run(..)` 等不含变量捕获的既有匹配继续可用。只有必要身份不可恢复时才按事实可用性给 Unknown，不能将身份缺失当作匹配成功。

### 3.2 首次声明与后续引用

首次声明只允许出现在可直接定位到当前候选声明的泛型子句直接槽位：

- 成员选择器的声明类型路径及方法名泛型子句；包括类型包含链、构造器和关联属性的声明类型。
- 独立类型模式中直接检查当前候选的有名类型路径泛型子句；数组等外包装不改变其直接候选位置。

以下位置可以引用此前可见的占位符，但不能首次捕获：返回/属性/参数类型的嵌套结构、特性类型、关系 `+` 的目标，以及首次声明泛型槽位内部的嵌套泛型/数组/可空结构。不能通过遍历多个特性或祖先反向决定一个新占位符。

例如，Declaration 中 `List<$T>` 对开放定义 List<> 可声明其自身槽位；`List<$T> && IEnumerable<$T>+` 后半段只检查先前确定的槽位关系。单独 `IEnumerable<$T>+` 或 `attr(call TagAttribute<$T>)` 首次引入变量则编译失败，提示使用 Capture 或先在直接声明处引入占位符。若通过其他合取已声明 `$T`，关系/特性位置仍可引用它。具体诊断归入现有变量声明/作用域诊断类别，不新增语法族。

成员中声明类型、方法子句仍先于返回/参数进行绑定分析。AND 保持可见占位符共享；OR 内新声明不向外逃逸，OR/否定中的首次声明约束沿用既有作用域规则。首次出现在禁止位置时给编译诊断，不静默切换到 Capture。

### 3.3 编译和运行结构

Binder 获得选项，将 Declaration 的新声明和引用编译为包含来源位置、声明层级及槽位的内部描述。每个引用都指向唯一声明描述；描述在编译后不可变。描述相对于原始 Match 候选，而非当前遍历到的祖先或特性，避免切换查询目标后错误重绑。

每次 Match 可建立一个按描述索引的确定槽位解析缓存，保存唯一的声明事实或失败事实。它不是“变量到多种候选类型”的环境，不为不同查询记录增加取值。首次声明的实际泛型项与预期自身槽位检查仍必须执行，不能只解析 OriginalDefinition 就跳过构造实参差异。

Declaration 的 OR、NOT、特性枚举、关系遍历只组合三态和诊断，不复制或合并 `BindingEnvironment`，不调用动态捕获的 RetainAlternative。先前的 `List<$L_i> || List<$R_i>` 组合因此不产生绑定环境笛卡尔积。不得以给 BindingEnvironment 加 IsGenericParameter 判断冒充此实现。

诊断及独立事实规则不变：已知匹配可决定关系存在性，部分闭包保留其诊断；仍不借优化改变 AND/OR/NOT 真值表、缺事实处理或已要求保留的诊断。没有必要为省分配而新增任意短路规则。

## 4. Capture 模式及预算

### 4.1 预算以内保留当前能力

Capture 仍允许 `$T` 捕获声明形参、具体类型、构造泛型或既有受支持签名；保留跨合取共享、OR 隔离、特性/祖先产生多种绑定及 Unknown 备选传播。候选身份比较、实例上下文区分、等价备选条件保持：变量键、签名实例和确定性均一致才合并。

现有行为测试中依赖具体实参捕获或多绑定的用例显式选 Capture。不得为了让旧测试全绿，把默认模式伪装成原动态捕获实现；Declaration 必须有独立正反例和无备选集路径证据。

### 4.2 两个有限约束

1. `MaximumBindingAlternatives`：每个合并备选集合中，去重后可保留的唯一备选数量。相同映射但不同 Unknown 标记仍是不同备选。它不表示整个进程最多存在这么多临时对象。
2. `MaximumBindingWork`：一次 Capture Match 共享的累计逻辑工作量。至少计入求值节点/候选访问、备选记录处理、绑定条目复制、绑定比较以及备选哈希/相等比较时访问的绑定项。每次创建备选记录和每个被复制/比较/哈希的绑定项各计一个单位；求值节点/枚举候选访问各计一个单位。重复备选不消耗唯一备选数量，但其处理仍消耗工作量。

所有 Fork、OR、NOT、属性/特性目标枚举和祖先遍历共享同一预算实例。每次 Match 创建新实例，不能挂在可复用编译计划或静态字段上。下一个候选和并发匹配互不消耗额度。

检查必须先于受控分配/复制/下一步处理；批量复制可先按已知条目数扣除额度，再执行实际复制。使用剩余额度检查，防止计数溢出。处理无限重复分支仍会耗尽工作量，不能因去重而无限循环。

### 4.3 增量收集，避免先放大后检查

以内部收集器逐项合并匹配/未知分支、去重、核验唯一数量并保存必要快照。`RetainAlternative` 及属性/祖先分支产生阶段就进入受控收集过程，不能先积累巨大的 EvaluationContext 列表再统一 ToList。Fork/Clone 中的字典复制同样预先计费。

保留当前实例身份比较，避免将结构上相似但携带不同后端查询上下文的值合并。每个中间集合遵守同一数量上限，累计工作量覆盖多个集合和临时副本。

### 4.4 预算耗尽的结果

预算不足时立即终止当前候选的整次 Match，返回 Unknown 并追加专用的预算耗尽诊断，建议使用当前未占用的 AN3007。诊断指明触发跨度、耗尽的是哪项预算及配置限额，并保留此前已收集诊断。不将其归为缺少后端能力、元数据损坏、类型深度或泛型元数超限。

不截断前 N 个备选、不优先删 Unknown、不将局部成功当作完整成功，也不在丢失绑定后继续执行后续表达式。整体中止是保守的资源结果，可能使本可算出确定结果的复杂表达式变为 Unknown，必须在规范和用户指南明确披露。

可使用专用内部中止信号，仅由两个 CompiledPattern.Match 入口捕获转换；不捕获外部 ITypeSystem 的任意异常。预算检查前优先检查调用方取消，取消继续抛 OperationCanceledException。没有 OutOfMemoryException 后恢复策略。

该预算控制核心内部的绑定处理和求值工作，不是墙钟超时或精确字节配额，不保证抢占正在执行的第三方 ITypeSystem 调用或改变后端闭包物化行为。既有原生限制、RegexTimeout、D01、U01/H1 均保持各自通道。

## 5. 兼容性与迁移

默认由 Capture 改为 Declaration 是显式的语义变更。原来用 `$T` 捕获具体实参、从特性/关系首次捕获、或通过多个绑定再筛选的调用，必须传入 Capture 选项。Capture 在预算内承诺保留原语义，不能以新默认模式为由删除该能力。

不含变量的表达式保持原语义；直接比较开放声明形参的常见用法保留。某些此前合法的变量表达式在默认模式变为编译诊断，另一些在具体构造候选上由 Matched 变为 NotMatched，迁移表须区分这两种变化。

无需修改 ITypeSystem 或其实现者。Cecil/Fody、Roslyn 源码/PE、Reflection 继续映射完整的定义和构造签名，不能为了默认模式重写中立元数据、丢掉实际实参或总是映射 OriginalDefinition。公开构造器/API 兼容与默认语义迁移分别验证。

## 6. 实施范围与验证要求

主要改动归属核心的选项/枚举、Binder/变量节点、声明槽位解析、EvaluationContext、BindingEnvironment/受控收集器、两种编译模式的 Match 入口、缓存键和诊断码；后端仅在证明映射事实不足时再单独评估，不预设需要修改。

验证至少覆盖：

- 默认及显式 Declaration/显式 Capture；错误枚举、错误限额、构造器兼容调用、配置不可变和模式缓存隔离。
- 类型与方法自身槽位、嵌套/外层槽位、不同声明同名/同位置形参、返回/参数中嵌套引用、具体构造及外部形参开放构造反例；不自动改用原始定义。
- 默认模式的合法声明与非法首次捕获、AND 引用和 OR/NOT 作用域；大量局部占位符 OR 组合不创建动态备选集。
- Capture 的原有具体实参、特性和祖先捕获回归；等价备选、不同实例身份、不同确定性及“后续只剩 Unknown 分支”的原反例。
- 数量边界、工作量边界、去重前后计数、创建/复制前中止、所有分支共享额度、下一次匹配重置、并发隔离及取消优先。
- 真实同源后端一致性与 Fody 独立执行；netstandard2.0 资产和 net472 宿主的有关兼容矩阵，不能只由核心中立测试推出跨后端支持。
- 保留有界分配量/操作计数及可复查压力证据；不使用脆弱的一秒墙钟断言冒充预算正确性，也不把本次局部测量称为已完成整体性能闸门。
