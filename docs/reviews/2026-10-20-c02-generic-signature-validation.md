## 根因与构造契约

原构造器只复制集合，没有验证声明元数、构造实参及原始定义是否一致。因此元数为 2、只有 `[int]` 的 `Box` 可以进入结构相等性与变量重绑定。此前将“构造器接受非空节点”推导为受支持输入，没有单独裁决其结构合法性。

当前边界如下：

| 输入 | 处理 |
| --- | --- |
| 类型定义，实参列表为空 | 允许；按现有规则合成形式槽位 |
| 闭合或开放构造，实参数量等于有效总元数 | 允许；`Box<int,T>` 的 T 是实际存在的第二槽 |
| 嵌套构造 | 实参列表包含外层槽位，按包含链总元数检查 |
| 非空实参列表少槽、多槽，或包含 null | 构造时拒绝，指出 `typeArguments` / `genericArguments` |
| 方法声明形参非方法所属，或位置与列表索引不一致 | 构造时拒绝，指出 `genericParameters` |
| 当前方法声明/构造与提供的原始定义元数矛盾，包括零元数 | 构造时拒绝，不再跳过零元数原始定义 |
| 将构造签名作为原始定义；类型原始定义身份不同 | 构造时拒绝，指出 `originalDefinition` |
| 方法未提供声明槽位及原始定义，仅提供实参 | 保留；实参列表自身确定元数，无法凭本地对象证明另一个声明的元数 |
| 完整槽位中的类型事实无法恢复 | 可用 `UnsupportedTypeSignature` 保留槽位；查询仍按所需事实处理 |

结构校验不解析程序集，不证明声明存在、泛型约束满足、所有类型形状均为 CLR 合法实参，也不扩大后端支持范围。超出 64 元数/深度的资源规则与本次数量一致性规则分开：结构一致的外部超限签名仍在匹配时得到原有限制诊断。

校验集中于核心内部 `GenericSignatureValidation`。集合只枚举一次并保留只读快照；类型数量通过逐层扣减检查，避免外部极端元数累加溢出。没有为结构相等性增加新的 Unknown 分支。

## 影响与资料同步

- `GEN-BINDING-001/S4`：构造拒绝及合法泛型/重复变量匹配。
- `SEM-REGEX-001/S4`：非法结构不进入正则，保留既有可格式化的合法定义及完整构造；声明上下文等所需事实不足时仍按既有 Unknown 规则处理。
- `USE-SHAPES-001/S1`：可空、元组与 tasklike 的缺失事实用完整槽位表示；非法零元数 Rest 构造被拒绝。
- 资源控制：原“零元数类型带 65 实参”的 fixture 改为“声明 65 元数且有 65 实参”，继续检验资源诊断，避免结构错误掩盖资源规则。

语言规范第 13.1 节、元数据可用性说明、使用指南第 12 节、知识库及来源批准引用同步。原始泛型 Finding 只追加适用性更新；历史失败及 19 例测试计数保持原值。用户入门、DSL、接口签名、适配器依赖和其他能力没有新增行为承诺，因此无需修改其余使用章节。
