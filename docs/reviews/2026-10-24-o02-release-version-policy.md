# O-02：统一正式版与预发布版本规则

日期：2026-10-24；来源 K3-M16；基准 `cc69141362727fc2ae9154467970865c5327ccc4`。本轮在现有检出目录实施，未跟踪审查资料和 README 的既有改动不纳入提交。

## 批准规则与实现

维护者决定采用 Rougamo 的基础版本加预发布后缀策略，并明确预发布由推送 `prerelease` 分支触发。参考为本机 Rougamo 提交 `8237bf203fa72d21fec18a4932a4cd1436f03dbe` 的项目版本与两份发布工作流；只读核对，未修改相邻仓库。AspectN 保留自己的完整验证、摘要和签名链。

根 [Directory.Build.props](../../Directory.Build.props) 显式集中 `VersionPrefix=1.0.0`，与修改前五个发布项目的 SDK 默认求值一致。正式 tag 必须逐字符等于 `v<VersionPrefix>`；预发布、`+build` 或版本不符的 tag 在还原前失败。此前讨论的 `0.1.0` 只是格式示例，没有据此调整项目基础版本。

新增 [get-release-version.ps1](../../eng/get-release-version.ps1)，检查基础版本唯一、无条件、三段数字且不含前导零、后缀或元数据，输出 JSON。预发布仅读取一次 UTC Unix 毫秒时间戳，产生 `preview-时间戳`；同一次运行的完整版本、前缀和后缀传递给还原、构建、测试及五个包的打包，完整版本继续用于消费者校验与后续制品交接。不新增手动完整版本覆盖入口。

[Release](../../.github/workflows/release.yml) 增加 `prerelease` push，保留正式 tag 入口。CI/Compatibility 的 dev/main push、相应目标分支 PR 和手动触发保持；CI 包 job 增加两个 PowerShell 宿主的版本脚本回归。签名发布 job 与基准结构完全一致，保留 `nuget-release` 保护环境、签前摘要检查、签名验证及发包步骤。工程操作说明见[发布版本指南](../../eng/release-versioning.md)。

## 当前验证与限制

[数据记录](data/2026-10-24-o02-release-version-policy.json)保存输入、结果、源码及产物哈希；本地日志位于 `artifacts/o02`，属于工程复核材料，不是已执行远端发布的证据。

- 新增黑盒回归先在缺少辅助脚本时失败；当前 PowerShell 7 和 Windows PowerShell 5.1 各 23 项通过。覆盖正式版本及七类 tag 拒绝、预发布输出、只读行为、缺失/重复/空/条件基础版本、非法数字及 XML 等输入。首次 Windows PowerShell 运行暴露无 BOM 中文注释吞掉后续时间戳赋值；Parser 的注释 token 证实原因，改用 UTF-8 BOM 并在 `.editorconfig` 声明后通过。
- 从实际 YAML 提取版本步骤执行 9 个用例，通过正式 tag、错误版本、预发布/元数据 tag、缺前缀及预期/非预期分支和引用类型检查。结构比对确认两种发布触发、版本步骤先于还原、11 处 dotnet 调用携带统一版本属性，签名 job、摘要及消费者步骤和 CI 触发规则保持。
- 实际 MSBuild 求值证明五个发布项目的默认版本未改变；正式和预发布的四项版本属性在各项目间一致。两轮完整解决方案还原及 Release 构建通过，各保留一项既有 net472 `System.Memory` 的 MSB3277 警告，零错误。
- 实际生成 `1.0.0` 和 `1.0.0-preview-1792780029103` 两组包，每组五个 nupkg、五个 snupkg。复用现有包验证器到消费者初始化前的完整内容/依赖/符号阶段，两组均通过且包哈希保持；另核对全部 20 个 nuspec 的版本。未向生产验证器添加跳过消费者的开关，也未削弱发布闸门。
- 使用本轮预发布的同一完整版本属性，执行解决方案 `dotnet test -c Release --no-build --no-restore -m:1`，八份 TRX 合计 2,436 项通过、零失败/跳过，含 net472 和 net10.0 兼容项目。受限环境中的测试宿主启动后无进展，停止后在正常本机环境重跑通过；不把项目测试当作 NuGet 消费者验证。

本机受限环境的默认构建未提供具体错误，诊断构建在共享编译器管道连接处停留，终止后用串行及非共享编译完成；还原另因无法访问 NuGet 的漏洞数据源报 NU1900，经授权在正常本机环境重新还原通过。这些本地验证参数没有写入发布工作流，也没有禁用漏洞审核。日志保留环境失败，不将它解释为版本策略缺陷。

本次未重跑完整消费者流程；[RM-13](2026-10-23-rm13-package-version-defaults.md)记录的 Roslyn/net472 `System.Memory` 冲突仍是独立已知阻塞，RM-14 也仅补核对包阶段。两组包的局部通过不代表十个消费者、远端 Actions 或完整发布已经通过。本轮未执行签名、推送、NuGet 上传或修改远端环境。
